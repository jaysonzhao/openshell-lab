= Prerequisites and Environment
:navtitle: Prerequisites and Environment

This workshop uses one multinode OpenShift {ocp_version} cluster. The raw
OpenShell sandbox environment supplies the OpenShell gateway and policy sandbox
(Modules 1 and 2). Secure Agent Workspace (SAW) supplies the cluster-resident
NemoClaw/OpenClaw runtime inside a per-user VM (Module 4). SAW is deployed
once — by the facilitator with the fleet install script (`automation/fleet/`),
or by you as the Module 3 prework before class.

== What you need

|===
| If you are… | You need

| Every participant
(Prerequisites, Modules 1, 2, 8)
| `oc` authenticated to the target cluster; Helm 3.x; Git, `curl`, OpenSSL,
`tar`, `install`, and standard Unix shell tools; the OpenShell CLI pinned to
`{openshell_version}` (installed below); both workshop checkouts
(see xref:#_get_the_workshop_checkouts[Get the workshop checkouts]).

| Module 4 — operate SAW
(core track)
| Everything above, plus: `virtctl`, `kubectl`, `jq`, GNU Make, SSH, `lsof`,
Python 3 with PyYAML on the control node; a Keycloak OIDC account for the SAW
gateway; the SAW checkout with its generated SSH key, namespace read access,
and assigned workspace details (facilitator-supplied).

| Self-deploying SAW
(Module 3 prework only)
| Everything above, plus: cluster-admin access and a dedicated workshop
cluster; at least 16 CPUs and 32 GiB of memory for software emulation, or
nodes with hardware virtualization available to OpenShift Virtualization;
capacity and default storage for operators, DataVolumes, the workspace VM,
image imports, and setup Jobs; Podman or Docker for image preparation and
registry authentication; an inference provider configured through the SAW
secret contract — never in workshop files or prompts; an
link:https://docs.nvidia.com/ngc/gpu-cloud/ngc-user-guide/index.html#generating-api-key[NVIDIA NGC API key^]
for the default inference provider.
|===

Web search is disabled by default in the SAW deployment; to enable it,
configure the `web-search` secret with a Brave or Tavily key and set
`enabled: true` on the `brave` provider in the BOM profile
(`charts/saw-bom/profiles/data-science/default/providers.yaml`).

Provided by the facilitators:

* A multinode OpenShift {ocp_version} cluster with cluster-admin: an OLM
  Subscription, cluster-scoped Agent Sandbox CRDs/RBAC, the privileged SCC for
  the sandbox service account, the `openshell` namespace, and a Helm release.
* The Agent Sandbox operator channel used by the raw OpenShell install,
  `{agent_sandbox_channel}`.
* A default StorageClass — the OpenShell gateway stores its SQLite data in a
  1Gi PVC.
* Cluster and registry egress sufficient to install Agent Sandbox, pull the
  Helm chart, and pull the sandbox image.
* SAW deployment with the fleet install script, unless you complete the
  Module 3 prework.
* One shared inference key for the SAW track: an
  link:https://docs.nvidia.com/ngc/gpu-cloud/ngc-user-guide/index.html#generating-api-key[NVIDIA NGC API key^]
  for the default `nvidia/nemotron-3-super-120b-a12b` model, provisioned
  through the SAW secret contract (`values-secret.yaml` → Vault). It covers
  every cluster and participant — no model key is needed from you on the SAW
  track. The guardrails module (Module 8) is the exception: bring your own
  Model-as-a-Service key and enter it at install time.

Rules:

* Match the client to its gateway: `{openshell_version}` for the raw OpenShell
  track, `{openshell_saw_version}` for the SAW guest gateway. Do not mix
  client and gateway versions.
* The raw policy track requires no model API key; the SAW track's key is
  facilitator-provisioned through the secret contract.
* The standalone NemoClaw CLI (`nemoclaw onboard`, local container-runtime
  workflow) is not used by this workshop. The SAW integration installs a
  BOM-configured NemoClaw runtime in the VM and provisions its sandboxes
  through the OpenShell gateway.
* Windows: the native Windows binary does not provide the Kubernetes/VM driver
  workflow used here. Install WSL2 with Ubuntu and run the Linux x86_64
  instructions inside it (keeping `openshell`, `oc`, `helm`, `virtctl`, the
  SAW SSH key, and `make`/`jq` in the same WSL2 environment), or use a RHEL 10
  or Fedora bastion for SAW deployment, gateway configuration, and
  troubleshooting — Windows users can use the browser-based Control UI and SSH
  to the bastion.

== Install the command-line tools

If you do not already have the tools, install `oc` from
the OpenShift console's client download page or the
link:https://mirror.openshift.com/pub/openshift-v4/clients/ocp/[matching client
release^], and Helm from the link:https://helm.sh/docs/intro/install/[official
instructions^].

Install the exact OpenShell client from the workshop repository root. The
installer selects the Linux x86_64, Linux ARM64, or Apple Silicon artifact:

[source,bash,subs="attributes+"]
----
OPENSHELL_VERSION={openshell_version} \
OPENSHELL_INSTALL_DIR="$HOME/openshell-cli" \
  ./automation/bootstrap/install-openshell-cli.sh
export PATH="$HOME/openshell-cli:$PATH"
----

Persist that `PATH` setting in the control node's `.bashrc` or `.zshrc`. Do
not use an unpinned latest installer for this workshop.

For SAW VM inspection and troubleshooting, install `virtctl` from the
OpenShift console client download that matches the cluster, and keep the
SAW-generated SSH key on the same workstation.

== Verify the command-line tools

Run the baseline check in every new terminal:

[source,bash,subs="attributes+"]
----
for tool in oc helm git curl openssl make; do
  command -v "$tool"
done
oc version --client
helm version
test "$(openshell --version | awk '{print $NF}')" = "{openshell_version}"
----

Expected result: every tool prints its install path. The final `test` line is
the version pin — it fails if the installed OpenShell client is anything but
`{openshell_version}`.

SAW operation additionally requires these tools on the control node:

[source,bash,subs="attributes+"]
----
for tool in kubectl virtctl jq ssh lsof python3; do
  command -v "$tool"
done
virtctl version --client
python3 -c 'import yaml'
----

Expected result: the same — every path printed, `virtctl` reporting a client
version, and the PyYAML import exiting silently when present. The SAW guest
gateway reports the `{openshell_saw_version}` build — the expected Red Hat SAW
packaging suffix on the same compatibility line.

== Verify the workshop automation and SAW fork

Run the following commands from the `rhai-agent-security` repository root.
The raw OpenShell assets are in this repository's `automation/` directory. SAW
deployment assets remain in the Secure Agent Workspace fork and are used from
that repository directly:

[source,bash,subs="attributes+"]
----
test -f {automation_repo}/Makefile
test -f {automation_repo}/openshell-env/install.sh
test -f {automation_repo}/policies/sandbox-policy-quickstart.yaml
test -n "$(git ls-remote --heads {saw_repo_url} refs/heads/{saw_repo_branch})"
----

Expected result: silence. The `test -f` commands confirm the automation
checkout is at the repository root; the final command confirms the SAW fork's
`{saw_repo_branch}` branch is reachable, since the deployment assets are pulled
from it.

== Run the OpenShift pre-flight check

[source,bash,role="execute",subs="attributes+"]
----
oc whoami
oc whoami --show-server
oc get storageclass
oc auth can-i create subscriptions.operators.coreos.com -n openshift-operators
oc auth can-i use scc/privileged
----

`whoami --show-server` confirms you are authenticated to the intended cluster;
`get storageclass` confirms the default storage the gateway PVC will bind to;
both `auth can-i` checks must print `yes` — creating an OLM Subscription (the
Agent Sandbox operator) and using the privileged SCC (the sandbox service
account).

For a facilitator-provisioned SAW workspace, check the VM and setup Job:

[source,bash,role="execute",subs="attributes+"]
----
oc -n {saw_namespace} get vm,vmi,job
oc -n {saw_gitops_namespace} get applications.argoproj.io
----

SAW uses Vault and External Secrets Operator for provider credentials and SSH
material — do not reuse local NemoClaw environment variables as a production
secret store.
