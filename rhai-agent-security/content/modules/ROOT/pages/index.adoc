= Securing AI Agents on Red Hat AI
:navtitle: Introduction

From OpenShell to Secure Agent Workspace.

This workshop examines how OpenShell and Secure Agent Workspace (SAW) constrain,
operate, and troubleshoot AI agent runtimes on OpenShift. Participants deploy a
raw OpenShell environment, test policy behavior, and then operate a
SAW-provisioned NemoClaw/OpenClaw workspace.

An agent that can use a shell, network, credentials, and external tools needs
controls outside the model. The exercises focus on the resulting technical
boundaries: runtime isolation, identity, capability policy, secret delivery,
observable decisions, and controlled lifecycle changes.

The workshop progresses through these tasks:

. Deploy and inspect a basic OpenShell gateway and sandbox.
. Deploy OpenClaw on the raw pod boundary and inspect its runtime.
. Apply policy changes, test allowed and denied behavior, and correlate runtime
  evidence.
. Install SAW as prework — or use an environment the facilitator deployed with the fleet install script — so the in-class core track stays short: OpenShift Virtualization, OIDC, external secrets,
  and GitOps governance.
. Configure and validate an existing SAW deployment, regardless of who installed
  it.
. Run OpenClaw through the SAW NemoClaw path and inspect its effective controls.
. Inspect identity, secret delivery, VM isolation, and GitOps ownership in the
  deployed environment.
. Investigate a payments outage with the governance-scoped agent fleet.
. Deploy a NeMo Guardrails server on OpenShift AI, prove rails block sensitive
  input before the model call, and wire a client application.

== Learning objectives

By the end of the workshop you will be able to:

* Distinguish the OpenShell gateway, sandbox supervisor, and OpenClaw gateway.
* Deploy, inspect, and troubleshoot an OpenShell sandbox on OpenShift.
* Change network policy, verify L7 and binary constraints, and restore a known
  policy revision.
* Validate the VM, identity, secret, workspace, and GitOps resources in SAW.
* Run OpenClaw through the SAW-managed NemoClaw path without exposing the
  inference credential to the sandbox.
* Deploy a NeMo Guardrails server on OpenShift AI and distinguish the runtime
  sandbox boundary from the model boundary.
* Collect evidence that supports or limits a security claim.

== How to run the workshop

Each exercise identifies the state to change, the evidence to inspect, and the
result that must be verified. Do not treat command completion as proof. Compare
the observed resource, policy, or event with the stated pass condition before
continuing. Facilitators provisioning environments ahead of class: see
xref:14-facilitator-guide.adoc[Facilitator Guide].

== Choose your track by allotted time

The navigation groups the modules into two tracks plus a closing finale. Pick by the time you have:

* *Core track — about 2 hours in class*: Modules 1, 2, and 4. Deploy the
  gateway, prove policy enforcement on the pod boundary, then validate the
  SAW environment and drive the agent, and finish at the Guardrails Finale
  (Module 8). Module 3 (90–150 min) is prework done
  before class — or skip it when the facilitator deploys SAW with the fleet
  install script; either way, SAW is up before class.
* *Extended track — everything, about 5 hours total*: adds Modules 5, 6, and
  7 to the core — you set up everything yourself,
  including Module 3. The complete OpenShell → OpenClaw → SAW experience plus
  the fleet capstone — both tracks finish at the same Guardrails Finale.

Dependencies, so you can enter where your time allows:

* Module 4 (core track) requires a running SAW environment — deployed by the
  facilitator with the fleet install script, or installed by you as the
  Module 3 prework before class.
* Modules 5 and 6 require Module 4 (gateway configured, SAW validated).
* The capstone (Module 7) requires SAW and Module 4's client configuration
  only — the raw OpenShell modules (1-2) are not a prerequisite, so
  time-constrained participants can jump straight to it.
* Module 8 (guardrails) is fully standalone — it needs only the OpenShift AI
  foundation and your own Model-as-a-Service API key — and closes both tracks.

== Technical model

OpenClaw gives an agent useful tools. OpenShell decides which tools and
destinations it can actually use. Secure Agent Workspace adds an enterprise
operating model around that boundary: identity, per-user isolation, secret
delivery, GitOps policy, and auditable access. NeMo Guardrails adds the third
layer: a model boundary in front of the LLM, where input and output rails
limit what the model receives and returns. The three layers are complementary:
OpenShell limits what the agent can execute, the workspace controls what the
agent runs on and who can reach it, and guardrails limit what the model
receives and returns — no single layer is comprehensive on its own.

[quote]
Capabilities are explicit, scoped, enforced outside the model, and visible to
operators.
