== Evidence interpretation

[cols="1,2,2",options="header"]
|===
| Topic | Supported interpretation | Required evidence

| Sandbox policy
| The declared filesystem, process, and egress policy is enforced by the
  OpenShell supervisor and visible through CLI inspection and audit.
| Exact behavior can vary by OpenShell version and image.

| Provider access
| SAW governance validates approved provider profiles and fails closed for its
  configured interceptor bindings when the interceptor is unavailable.
| Do not infer that every profile rule is live HTTP method enforcement without
  testing the target version.

| Network isolation
| OpenShell supports deny-by-default egress, binary binding, and L7 method
  controls; the SAW integration adds Git-managed governance profiles.
| Test the specific host, binary, route, and policy version in the target lab.

| NemoClaw on OpenShift
| SAW integrates a BOM-configured NemoClaw runtime inside a per-user VM on OpenShift.
| Do not claim that standalone `nemoclaw onboard` manages a remote OpenShift
  gateway; verify the deployed SAW image, gateway, and BOM versions.

| VM isolation
| This workshop SAW profile provisions a dedicated KubeVirt VM for its
  configured owner.
| Confirm the VM owner configuration, namespace mode, and VMI state. Do not
  infer automated multi-user provisioning from one deployed release.

| Human approval
| The capstone incident flow requires a UI confirmation before its fixed
  remediation action.
| Do not describe that confirmation as durable, identity-bound approval evidence
  unless the environment records and retains such an event.
|===

== Model-boundary extension

NVIDIA NeMo Guardrails adds guardrails at the application or model boundary.
It complements OpenShell; it does not replace the sandbox. OpenShell limits
what the agent can execute, while application-level guardrails limit what the
model receives or returns.

Module 8 installs and exercises this integration:
xref:13-module-08-model-boundary-guardrails.adoc[Module 8: Model-Boundary
Guardrails] deploys the guardrails server with the TrustyAI operator, tests
rails through the OpenAI-compatible API, probes rails in isolation, and wires
a client application. The `nemo-guardrails` chart lives in
`automation/charts/nemo-guardrails`. The guardrails boundary is not part of
the OpenShell sandbox claims above; its pass conditions are stated in Module
8 and verified there.

== Workshop evidence bundle

Retain these artifacts when recording workshop results:

* The effective sandbox policy and a sample audit event.
* The architecture diagram identifying the OpenShift cluster, raw OpenShell
  sandbox environment,
  SAW VM, OpenClaw/NemoClaw,
  Keycloak, Vault, and the governance interceptor.
* A capability matrix mapping each agent to its allowed backends.
* The deployed boundary: raw pod-based evaluation or the configured-owner SAW VM.
* A validation plan covering identity, secrets, policy enforcement, audit,
  observability, and human approval.
